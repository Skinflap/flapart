# Reviewed Qt source bundle v5

This is the frozen22file Linux/macOS Qt5 backport input, not a desktop release. receipt.json records original/revised hashes and upstream patch provenance. apply.py verifies the receipt and all patch/input/output hashes, refuses symlinks and already modified inputs, and changes only the explicitly supplied private source tree. The entire source checkout must independently match the recorded revision expectations; this helper verifies only changed files.

Run `python3 apply.py --private-source /absolute/private/qt5 --output /absolute/new-evidence.json`. The private source must contain exact qtbase, qtdeclarative and qtsvg submodules. All22files applied and matched their expected after hashes in a disposable validation; originals remained intact and repeat application was refused.

Build Core, Gui, Network, Xml, Quick and Svg and any required dependent outputs in a fresh prefix. Compare generated feature metadata before adoption. Mac must follow the original recipe's separate arm64/x86_64 Qt5 builds and verified universal assembly. Run focused regressions and full application/Python/TLS/installer tests against the resulting exact artifacts.

QtImageFormats must use maintained systemWebP1.6.0. This source patch bundle alone does not fix statically embedded WebP1.2.1 in original Windows/Mac plugins. Verify actual binary dependencies and decoder loading, and include final decoder sources/notices. Linux original newbuild already has systemWebP1.6.0 proved by configuration, imports and actual encode/decode/mapped-library evidence.

Windows additionally requires the separate GDI fix under review (QtFontDatabaseSupport/qwindows plugin); v5 must not be treated as the final Windows patch set. The full dependency advisory and source/distribution review also remains separate from Qt catalog coverage. Original licenses and source copyright headers are preserved; see LGPL3/GPL2/GPL3 license files and the exact original file terms.

Mac preparation: `prepare-macos.py --original-source ORIGINAL --work FRESH` exports the pinned superproject and nine module commits, applies v5 plus the original Mac platform patch, and hashes the complete source. It preserves retained sources. `build-macos.py --prepared FRESH --maintained-sdk SDK --work NEW --jobs 2` requires native macOS and maintained OpenSSL3.5.9/WebP1.6.0 inputs, copies the SDK, configures each CPU through `arch`, runs the normal ordered build, compares nine feature groups before installation, and stages each installation separately. It invokes strict universal assembly after checking required framework and WebP variants; it does not adopt outputs. The driver has recipe-argument/syntax/host-refusal validation only; native execution, assembly of the new Qt builds, binary dependency audit and application qualification remain outstanding. Windows now has the separate consolidated v6 bundle; v5 remains frozen for Linux/Mac.

The merger requires matching path/type inventories, CPU-specific native inputs, identical ordinary files/links, and exact-hash review for generated metadata differences. It verifies both extracted output slices against their inputs, refuses unsafe links and existing output paths, and records hashes. Eight actual clang/llvm-lipo fixture tests pass, including static archives and refusal cases. The retained original Mac QtCore and WebP binaries also passed exact-slice reassembly under `qa/macos-build/universal-assembly-fixture-v1`; this is assembly-tool evidence, not patched runtime qualification. No metadata differences are preapproved.

`promote-macos.py --build-work BUILD --output RECEIPT` stages Qt over the disposable build SDK, verifies exact assembly hashes, replaces all baseline framework binaries, checks both CPU slices for maintained TLS/WebP imports, and preserves the prior SDK as sdk-before-qt. Five real Mach-O fixture tests pass. It never updates the original maintained SDK or public package. Packaging must validate both the original TLS promotion and this new Qt promotion; that integration and actual rebuilt application testing remain required.

Do not run whole-tree `qmake_all` before the ordinary build. The Linux application test established that doing so can omit QtQuick/QML registration sources before qmltyperegistrar installs its build feature. The Mac driver now preserves normal ordering and records generated registration source hashes. Source checks do not replace the subsequent native QML/application smoke test.
