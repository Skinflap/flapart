# Hosted Mac exact-candidate follow-up: proposed exchange

Design only, 2026-10-16. No workflow, enrollment, dispatch, upload or release mutation performed. No retained Mac candidate has yet been established. This is a proposed implementation, not an already tested transport or native qualification.

## Available authority and mechanism

Read-only live checks found `Skinflap/flapart` PUBLIC, the existing local `gh` session ADMIN, Actions enabled with all actions allowed, and no releases/drafts listed. Current build workflow grants only `contents: read`. No credentials or key material were inspected. Local admin membership does not prove every required token scope; an eventual harmless rendezvous fixture must test actual access before sending a candidate.

Use two fresh hosted jobs, `macos-15` / arm64 and `macos-15-intel` / x86_64, with independent ephemeral encryption keys. Current [GitHub runner documentation](https://docs.github.com/en/actions/reference/runners/github-hosted-runners) lists both labels and gives each standard job its own VM. This avoids Rosetta installation or accepting additional software terms. Measure actual child architecture; labels alone are insufficient. If Intel availability changes, ARM plus Rosetta is an alternative only after explicitly checking actual translated execution and preserving separate fresh jobs/profiles.

The local machine recovers and verifies the original retention envelope; its long-lived private key never leaves its protected local GPG home. Each runner exports only a fresh public key as a narrowly scoped artifact. Artifact v4+ is readable while the job remains active, according to the [official artifact toolkit](https://github.com/actions/toolkit/blob/main/packages/artifact/README.md). The reverse leg uses an **encrypted-only temporary draft release asset**, uploaded by the existing local authenticated session. The documented public [Actions REST API](https://docs.github.com/en/rest/actions/artifacts) has no general local artifact-upload endpoint: do not export runner runtime tokens to simulate one.

Draft listings are restricted to push-capable users; release-asset upload needs repository contents write access. See [release API](https://docs.github.com/en/rest/releases/releases) and [asset API](https://docs.github.com/en/rest/releases/assets). Therefore the proposed rendezvous job needs reviewed `contents: write` for draft access, rather than assuming current read-only permission suffices. It uses only GET requests; local tooling creates/deletes the draft. No new PAT, CI secret, SSH/VNC service, paid runner or private host is required by this design. Keep that token out of candidate process environment and command logs. A same-UID native program remains inside the hosted job's trust boundary; this is not a sandbox against a malicious candidate.

## Exact sequence and binding

1. **Local preflight before dispatch:** download the authenticated original encrypted artifact, retain ciphertext SHA/build run/commit, decrypt through `retain.py`, expand transport-v2 if applicable, and verify the real packaging chain plus candidate inventory. Pin original candidate ZIP SHA/size and inventory SHA. No rezip, re-sign, modified application/plugin bytes, source rebuild or original secret export. Create a small explicit transfer root containing ZIP, inventory, original candidate manifest and a local verification receipt referencing the original chain. Keep full multi-gigabyte stage evidence local. The latter receipt is an operator assertion, not a replacement chain proof or source-qualification result.
2. **Manual workflow inputs:** immutable helper commit, original build identity, candidate SHA/size, inventory/manifest SHA, expected operator numeric GitHub ID, unique exchange ID and deadline. Validate exact types/lengths before use; never interpolate input into shell code. Checked-out helpers/installer/probe are separate explicitly hashed test inputs; they do not overwrite app bundle bytes. Workflow is dispatch-only on reviewed code, no PR/untrusted checkout, checkout credentials not persisted. Use concurrency keyed to exchange ID and do not cancel an existing live exchange automatically.
3. **Fresh job setup:** fail first if current Flapart profile/settings exist; verify a real GUI login session (`/dev/console` UID equals job UID, `launchctl print gui/<uid>` succeeds), record macOS/version/available disk and GPG version. Check `open` supports `-n -W --arch`. Do not substitute offscreen Qt or fake CI/UI variables. Give job 120 minutes, exchange poll 45 minutes, and native launch its existing bounded timeout.
4. **Ephemeral key:** mode0700 short-path temporary GPG home outside checkout/output, umask077. Generate a single encryption-capable key with at most one-day expiry and no passphrase, because no human unlock secret is available to the ephemeral VM. For example reviewed GPG `--batch --pinentry-mode loopback --passphrase '' --quick-generate-key <nonpersonal-run-UID> rsa3072 encr 1d`. Never export its secret key. Export ASCII public key, full primary fingerprint, its SHA, random 256-bit nonce, repository/workflow/run/attempt/job/architecture/commit/deadline as `request.json`. Upload **only** public key and request, with run+attempt+architecture in artifact name and one-day retention. Do not upload the directory holding GPG state.
5. **Local authentication:** fetch that exact artifact ID through authenticated GitHub API; verify run's workflow path, event, head SHA, actor, attempt and still-running job against the intended dispatch. Verify artifact digest, public-key SHA/full fingerprint and request fields. Never accept a key copied from a comment, anonymous URL, or only an abbreviated key ID. Abort stale/replayed/nonmatching requests. No run rerun may reuse an old key or response.
6. **Response:** use existing `retain.py encrypt` with explicit inventory and that runner public fingerprint. Its inner transfer receipt repeats request nonce, candidate pins, run/attempt/architecture and deadline. Create a draft release via local `gh api` using a structured JSON file with `draft:true`, `make_latest:false`, a unique temporary tag name and reviewed target commit. Record returned release ID; never call publish. Upload ciphertext and a small response JSON last. Response includes exact asset IDs/names/bytes/hashes, full recipient fingerprint and all request bindings; no plaintext candidate or paths. Each release asset must be under [2 GiB](https://docs.github.com/en/repositories/releasing-projects-on-github/about-releases). Minimal first implementation rejects larger ciphertext; a later bounded chunk protocol may support it, but must pin each chunk and the concatenated SHA before decryption.
7. **Runner polling:** bounded authenticated GET of the unique draft; require draft true, no published timestamp, expected author ID, expected target commit, exact exchange identity. Require response/ciphertext uploader IDs match the expected local operator and one matching complete set of assets. Check pins again after download; follow only GitHub API's documented asset redirect without forwarding authorization to an arbitrary origin. Do not log signed download URLs. GPG confidentiality alone does not authenticate sender: API identity, immutable dispatch candidate SHA and nonce binding are mandatory. Download each asset once into fresh private files, validate bytes/hash and call `retain.py decrypt` with ephemeral GPG home. Reject unexpected inner paths, extra files, mismatch or expiry. Refuse any response update after admission.
8. **Actual installer journey:** launch the existing driver on its actual hosted VM:

   ```text
   python3 native/installers/macos-online/ci_e2e.py \
     --archive <exact recovered candidate.zip> --archive-sha256 <dispatch SHA> \
     --manifest <pinned original manifest.json> \
     --probe native/qa/portable \
     --architecture <arm64 or x86_64> --output <fresh private evidence>
   ```

   Validate actual child image hash/path, architecture and execution mode, Qt orderly shutdown, PNG/KRA roundtrip, launcher path and preservation receipts. Never run both architectures through one persisted user profile. The updated driver tests initial native launch, corrupt upgrade refusal, same-bytes upgrade preservation and a second launch of the selected upgraded edition with actual image/architecture/exit checks. That implementation still awaits native execution; it does not prove browser authentication/posting or downloaded-user security approval. Do not claim those outcomes. Additional installed-path TLS/Python probing needs a scoped driver extension because its temporary installation is currently removed on exit; it cannot be claimed from earlier relocated-package probes.
9. **Evidence and cleanup:** encrypt an explicit output inventory to the existing local public retention recipient and upload only that ciphertext plus a bounded public status/digest receipt. No whole-workspace glob or raw process environments. Include failure-first E2E output, exact helper/input hashes, both original and test-only installer manifests, ciphertext admission pins, native child evidence and launcher/security logs. On success/failure/cancel, best-effort `always()` cleanup stops only the ephemeral GPG home's agents and removes its home and private plaintext. Local coordinator deletes only its recorded draft and assets after evidence recovery, or on timeout; verify no tag was accidentally created before deleting any matching temporary tag. Hard cancellation can skip cleanup: ephemeral VM teardown is the final boundary, not a claim of SSD secure erasure. Never persist key/home via cache/artifact. An expired key's ciphertext cannot be recovered after teardown; retry requires a new run/key/exchange.

## Actual remaining blockers, not a private-Mac requirement

- A candidate and verified original encrypted retention envelope do not exist yet. No workflow should pretend to reuse one.
- Rendezvous helper/workflow does not exist. Implement/test strict request/response authentication, expiration/replay, asset identity, archive limits and cancellation. Run a harmless encrypted fixture to prove draft GET permission and during-run artifact retrieval with the actual tokens before a candidate exchange. No permission changes were performed here.
- Hosted GUI and LaunchServices behavior must be measured. The installer currently records `spctl` denial without bypassing it; launch might be blocked for the ad-hoc app. Do not disable Gatekeeper, clear quarantine, automate Open Anyway, re-sign, or claim manual approval happened. A blocked dialog is a truthful failed/blocked journey. A hosted-runner local archive also cannot qualify the separate downloaded-user approval experience, even if launch succeeds.
- Measure candidate expanded bytes and free disk immediately before decrypt/install. Budget ciphertext + decrypted ZIP + encryption plaintext staging + **two expanded installed editions** + evidence and safety margin; no SDK/build tree is needed. Published runner storage figures do not establish real free space. Reject before starting if insufficient.
- Public logs/artifacts are not confidential. Keys are public; candidate and detailed diagnostic evidence remain encrypted. Draft access is defense in depth, not the confidentiality mechanism. Trust in GitHub's hosted VM and the reviewed job/candidate remains necessary.

This design can test both real Mac architectures without Mitchell owning a Mac. A successful result would be exact-candidate installed-runtime evidence only, never source closure, notarization or public release qualification.
